# 设计取舍与后续

本文记录「为什么这么做」，以及还没做的东西。使用说明看 [README](../README.md)；Agent 详情页用的是一张示意图（`docs/DETAIL*.md`），所以设计笔记单独放在这里。

## 形态：为什么是 DSH 插件，而不是独立 Web 应用

比较过三条路：

| 形态 | 好处 | 代价 |
|---|---|---|
| 独立 Web 应用（Electron/Next） | 界面自由 | 稿件在 DSH 对话里写、复盘要在另一个应用里看，数据得来回搬；工具、定时、配置、凭据都得自己重造 |
| 塞进某个已有内容仓库的 CLI | 最快 | 和那个仓库的文案库耦合；换个号、换个内容型就得改仓库 |
| **DSH 插件（选中）** | 复盘就在写稿的同一个对话里；复用 DSH 的工具注册、定时任务、配置与凭据 | 跟 DSH 版本绑定（锁 `engines.dsh`）；面板受槽位限制 |

关键约束：**核心逻辑不碰宿主 API**。`lib/` 里全是纯函数（`buildRows`、`buildReport`、`buildPack`），只有 `index.js` 和 `lib/tool.js` 认识 `ctx`。将来要出 CLI 或独立页面，把那两个文件换掉即可。

## 占用：三类，只有一类是真成本

被问过「会不会加 DSH 的占用」。分三类答：

1. **内存/进程**：插件默认不新起进程，是个纯 JS 模块，常驻几 MB；起进程只有两处、都要你点一下——「扫码登录」和「采集并导入」，各自 `spawn` 一次 Python 脚本，跑完就退（见「为什么允许这一处起进程」）。实测宿主基线 13 个进程、RSS 合计 3346.4 MB（最大两个 923 MB / 812 MB），插件在这上面是零头。
2. **客户端首屏**：面板不设 `immediately`，打开才加载，约 20–40 KB；不打开面板就是零成本。
3. **每轮 token（真成本）**：每个工具每轮都要进系统提示，一个工具约 150–250 token；拆成五个工具就是 400–800 token/轮。所以：
   - **只注册一个 `media` 工具**，用 `action` 分派；
   - `description` 压到四行，参数描述一句话；
   - 返回值只给数字和短句，不返回整段复盘文本（`pack` 例外，它本来就是文本）。

## 隐私：数据只落在本机指定目录

- **不联网**：`lib/` 与 `index.js` 不 import `fetch` / `http` / `https` / `net`，插件没有任何出网路径，`test/smoke.mjs` 里有一条断言守着这个事实。
- **默认不起进程，例外只有登录与采集**：`lib/bridge.js` 允许 `spawn` 一次 `scripts/` 下的白名单脚本（`login` 用户 2026-11-18 批准；`fetch` 同日经用户裁决「面板加一个『采集并导入』按钮、手动触发、不自动」批准），取舍见下一节。`lib/` 其他文件与 `index.js` 仍然零 `child_process`，`shell: true` 从不出现，`test/smoke.mjs` 有三组断言守着（bridge 之外零命中、`spawn` 全仓库只出现一次、无 `shell: true`）。采集与解绑拿不到宿主注入的 `workspaceRoot` 就拒绝执行，不回落 `process.cwd()`（原因见「删凭据删错了目录」一节）。
- **台账位置**：默认 `~/media-ledger`（仓库外）。配置 `dataDir` 指哪写哪；仓库的 `.gitignore` 已忽略 `data/` 与 `*.jsonl`，即使有人把目录指进仓库也不会被提交。
- **仓库里没有数据**：本仓库只有代码、文档、自测；作品与数据是使用者自己的，不进版本库。

## 为什么允许这一处起进程（登录与采集）

0.5.2 之前这个仓库的规矩是「`lib/` 里零 `child_process`」。这一版开了一个针孔：面板上的「扫码登录」与「采集并导入」两个按钮，各自会起一次 Python 采集脚本。为什么不干脆放宽这条规矩，而只开一个针孔：

- **用户点击就是显式意图**。触发点只有两个——人在面板上按下「扫码登录」或「采集并导入」。没有定时任务、没有后台预热、没有「顺手帮你刷新一下」，所以不需要解释「谁、什么时候、跑了什么」。
- **白名单三个脚本**。平台只认 `bilibili` / `douyin` / `xhs` 三档，各自映射到一个固定脚本与固定子命令（`scripts/bili_sync.py login`、`scripts/douyin_sync.py login`、`scripts/xhs_sync.py login`）。表外的平台直接回 `no-collector`——视频号至今没有采集脚本。
- **只跑 `login` / `fetch` 两个子命令，而且都要人点一下才跑**。0.5.2 时这里只放了 `login`（只拿凭据、不搬数据），`fetch` 留在命令行由人自己敲。0.5.7 按用户裁决把 `fetch` 也接了进来——他要的正是「登录完就能在面板里看到数据」，而搬数据的代码本来就在同一个 Python 进程里，插件本体仍然一个请求都不发（不联网这条没有松动，松动的是「谁触发那次进程」：由人点按钮，而不是由代码自己排期）。采集没有定时、没有后台预热、不点就不跑；产出只落在工作区根的 `tmp/` 下，导入前先看退出码，非 0 一律不导入（半份 JSON 灌进 append-only 的台账撤不回来）。
- **不传任意参数**。`platform` 走枚举，`account` 走 `^[A-Za-z0-9_-]{1,32}$`（与脚本正则一致；省略时按 `main`），参数是拼进 `spawn` 的数组而不是 shell 字符串，`shell: true` 从来不出现——命令注入没有着力点。
- **登录 330 秒 / 采集 30 分钟超时 + 单任务互斥**。脚本自己等扫码的上限是 300 秒（B站与小红书；抖音 `login --timeout` 默认 180），桥的 330 秒是给它留出启动浏览器与收尾的余量；采集放宽到 30 分钟（50 条要从创作中心一页页翻），到点就 kill——挂住的进程不会一直占着。同一时刻只允许一个任务（登录与采集共用同一个槽，解绑在任务跑着时被挡住），再点一次直接回 `busy`：两个脚本抢同一个浏览器只会互相踩。
- **回收时 kill**。插件 dispose（重装 / 停用 / 退出）时把子进程杀掉，不留孤儿；日志只留尾部 2000 字符给面板排错，不落盘、不进仓库。

边界：这条例外**只能用于登录与采集这两个子命令**，它不是「执行器」的雏形——不接任意命令、不接任意路径、不接任意参数，也不接受「反正已经有 spawn 了，顺手再挂点别的」这种扩张。`spawn` 的命令与参数由纯函数算出来（`lib/fetch.js` 的 `buildFetchPlan`、`lib/bindings.js` 的 `buildUnbindPlan`），产出文件名是我们自己拼的 `panel-fetch-<平台>-<账号>.json`，账号名先过 `^[A-Za-z0-9_-]{1,32}$`，`shell` 永不开；采集产出必须落在宿主注入的工作区根下的 `tmp/` 里，**拿不到工作区根就回 `no-workspace` 什么都不做**。`test/smoke.mjs` 用多组断言把这层皮钉住：`bridge.js` 之外零 `child_process`、`spawn` 全仓库只出现一次、`shell: true` 零命中，解绑另外四条——坏账号不留文件、只删算出来那两份、再删一次幂等、**没拿到工作区根一个文件都不删**。要放宽先改断言——那一步会强迫改动者先跟用户确认，而不是悄悄扩散。

## 2026-11-18 的一次真事故：删凭据删错了目录

做解绑时第一版写的是「拿不到宿主注入的 `workspaceRoot` 就退回 `process.cwd()`」，测试也照着这个写——测试能过，因为它先 `chdir` 到临时目录再跑。而真实插件进程的 cwd 不在工作区（桌面版插件进程的 cwd 是宿主安装目录），于是那一次真解绑**没有回 `no-workspace`，而是顺着 cwd 拼路径删掉了 `config/bilibili_main.txt`（当时的扩展名；0.5.9 起改叫 `.json`）与它的 `.identity.json`**：B站凭据和昵称一起没了，只能重新扫码。

三处教训，都落成了断言：

1. **「取不到就用 cwd 顶上」是危险默认值**。cwd 不是用户的意图，只是进程碰巧所在的地方。涉及删除、写入的路径，宁可拒绝执行也不要猜。
2. **测试自己 `chdir` 会掩盖这个 bug**。回归断言反过来写：在 `decoy-ws` 里放一份同名凭据，`process.chdir(decoyWs)` 之后用**没有** `workspaceRoot` 的路由去解绑，必须回 `no-workspace` 且文件还在。
3. **删文件前先做纯函数校验**。坏账号名现在由 `buildUnbindPlan(platform, account, '')` 先挡成 `bad-account`，不会再因为「根也没拿到」被误报成 `no-workspace`——错误码要指向真实原因。

解绑删的是凭据不是数据，但凭据丢了照样要人重新扫码，代价和丢数据差不多。这条路径上以后任何「顺手回落一下」的念头，先回来看这一节。

## 存储：为什么是 JSONL 而不是 SQLite

- `better-sqlite3` 要 node-gyp 编译，Electron ABI 一变就挂；纯 JS 的 `sql.js` 要整库读进内存再写回，没必要。
- 数据量是「两条作品 → 一年几百条 × 十几次报数」，万行以内。JSONL 一行一条，`git diff` 看得见每次报数，出问题能手改。
- 快照表不建索引，靠 `latestSnapshots` 一次线性扫描算最新（几千行级别，毫秒）。

代价：并发写没有锁。当前是单进程、人手动报数，够用；如果哪天要自动导入导出表并发写，得加文件锁或改成单写入队列。

## 口径：三条踩过的坑

1. **最新快照要按真时间取**。原先用 `String(captured_at)` 比大小，`2026-11-17T09:00` 会压过 `2026-11-17 18:00`（`'T'`(0x54) > `' '`），`2026-9-5` 会压过 `2026-11-15`（`'9'` > `'1'`）。现在 `parseTs` 支持 `YYYY-MM-DD`、空格/`T` 分隔、带秒、斜杠，解析失败按出现顺序兜底。
2. **中位数不用均值**。一条爆款能把均值拉到没有参考价值。
3. **互动率分子分母必须同批**。曾经出现 10050%：分母只累加「有播放」的行，分子却累加所有行。现在只在同一条快照里同时有播放和互动时才进分子分母。

外加：缺值存 `null` 不存 `0`——评论 0 和「后台还没显示评论」是两件事。

## 发布包只做校验，不做上传

见 README 的「为什么不做上传」：官方接口对个人号关着，抓私有签名接口维护成本远高于收益，封的是自己的号。`pack` 做三件机械能做的事：标题字数（小红书 20 字是硬限制）、话题去重截断到 5 个、封面比例偏差 >2% 提示。

标题字数上限与封面尺寸都是**建议值**，可在配置里按平台覆盖——各平台后台的实际提示会变，写死在代码里迟早对不上。

（面板已在 0.5.0 落地，0.5.1 补上「四平台恒在 + 绑定状态 + 空态三步」：侧栏「自媒体台账」图标 + 台账/复盘两视图 + 两条本机桥路由（0.5.2 增到四条，0.5.7 增到七条）；0.5.2 再补「台账表按平台分组 + 面板内扫码登录」——分组只是展示分流（指标仍全部来自 Host 的 `buildReport`），登录是本仓库唯一的起进程例外。0.5.3 把登录从「只认 `main`」放开成多账号：账号名在面板里可填可切（规则与脚本一致的 `^[A-Za-z0-9_-]{1,32}$`，中文别名脚本不收），一个平台可绑多个账号，「已绑但还没有作品」的账号也会出现在左栏并被 Host 分到自己的空切片——否则点进去会 fallback 到全部切片，看到别人的数。用法见 README 的「左侧栏面板」，不再列为待做。0.5.7 再补「采集并导入 + 解绑」：采集是手动触发的一次 `fetch` 加一次导入（退出码非 0 一律不导入、`account` 覆盖成凭据别名），解绑只删凭据与身份文件、台账一行不动；两条路径都要求宿主注入的工作区根，拿不到就拒绝执行。）

## 还没做
- **半岁对比 / 周报**：借鉴公开项目 `mdldm-maitian` 的「发布后第 1/3/7 天出卡片、跟上一期同龄比」；数据够两条以上再上，真实台账还没铺开，做了也是装饰。
- **导入平台导出表**：平台后台只留 30 天、最后 100 条，手抄会丢历史。导出表的列名各平台不同，需要先拿到真实表头。
- **定时提醒**：DSH 有 schedule 能力，但提醒文案与频率得先定；目前靠人记得。
- **npm 发布**：`dsh-media-ledger` 在 npm 上未被占用，但插件还在自用阶段，先不占用名字。

## 已知限制

- `media` 工具有 28 个参数（一个工具的统一代价），模型偶尔会把 `list` 的筛选条件写到 `report` 上；参数描述里已经写明各自属于哪个 action。
- 台账目录里的 `posts.jsonl` 只会追加，改标题要手改文件；`--fix` 这类更正命令没做。
- 时间一律按**本地时区**理解，不处理跨时区。
